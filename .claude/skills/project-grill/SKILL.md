---
name: project-grill
description: Interview the user about a project until you both share one understanding of it, recording every decision in playbook.md.
---

Interview the user about every part of the project until you share one understanding: the idea and its users, architecture, technologies, repos and git host, deployment, and API conventions.

- Ask one question at a time and give your recommended answer with it, so the user can simply confirm.
- Follow each answer down to the decisions that depend on it before moving to the next topic.
- If existing files can answer a question, read them instead of asking. When `playbook.md` already has a draft, confirm it and ask only about the gaps.
- Write each decision into `playbook.md` as soon as it is made, so nothing is lost if the conversation gets long.

You are done when the user confirms that `playbook.md` matches what you agreed.
